# Dev Containers

Container images and Dev Container features for `ghcr.io/froazin/devcontainers`, with the dev-time Python tooling that builds and tests them. Nothing is published yet: the build tags images locally. ## How an image is built and tested

1. `devel.images.image_dirs` finds each folder in `images/src` that has both a `manifest.json` and a `template.json`.
1. The build renders `template.json` with the manifest's fields into `.devcontainer.json`, then runs `devcontainer build` from the `@devcontainers/cli` npm package. The image is named `ghcr.io/froazin/devcontainers:<image>`.
1. The build tags the image with each manifest tag on its own and with `-MAJOR`, `-MAJOR.MINOR` and `-MAJOR.MINOR.PATCH` suffixes from `version`.
1. The tests run `/bin/sh images/test/<image>/test.sh` in a podman container of the built image, with the test folder mounted read-only at `/test-project`. A test fails when the script exits non-zero or the image isn't built. An image with no `test.sh` is skipped.

- Edit `template.json`, never `.devcontainer.json`. The build overwrites it.
- The template uses Jinja2's `StrictUndefined`, so a field the manifest doesn't have fails the render.
- The registry, owner and repository in image names come from `devel/images/config.py`, not from the manifest's `registry`, `owner` and `repo` fields.
- The `image-manifest` rule in `.claude/rules/` covers changes to a manifest, the schema, `ImageManifest` or a template.

## Commands

Run every command from the repository root. The paths in `devel/images/config.py` are relative, so a task run from a subfolder fails. Running `uv run` from another project, such as a sibling repository, uses that project's environment and fails with "Failed to spawn: invoke".

| Task | Command |
| --- | --- |
| Build every image | `uv run invoke build images` |
| Build some images | `uv run invoke build images --filter 'ubuntu-*'` |
| Build without the cache | `uv run invoke build images --no-cache` |
| Build, then test the images | `uv run invoke test images` |
| Test the images already built | `uv run invoke test images --skip-build` |
| Check the image manifests | `uv run invoke validate images` |
| Check shell scripts | `shellcheck images/test/*/*.sh .claude/hooks/*.sh` and `shfmt -d images/test .claude/hooks` |

- For lint, format, type check and unit tests, see [Commands](README.md#commands) in the README.
- Only the `images` suite exists. Any other suite, including `features`, prints a message and exits 0.
- `--filter` is a shell-style glob on the image folder name. A filter that matches no image exits with status 1.
- `--skip-build` takes an optional value, so put it after the suite. A value such as `--skip-build=false` still skips the build.
- A build runs `npm install` first, so npm must be on `PATH`. Node comes from nvm, through `.nvmrc`, which a non-interactive shell might not load.
- The Dev Containers CLI builds with `docker`, and the build then tags the image through the podman Python client. `docker` must be podman, such as the podman-docker shim, and podman's API socket must be running.
- `shellcheck` and `shfmt` aren't project dependencies. They read `.shellcheckrc` and the `[*.sh]` section of `.editorconfig`.

## Python conventions

- Python 3.14, Ruff with a line length of 120 and Pyright in standard mode.
- `devel/` holds dev-time scripts only. uv doesn't build or install it: `tasks.py` imports `devel.images` because Invoke puts the repository root on `sys.path`, and pytest does the same through `pythonpath`.
- Keep `devel` packages free of Invoke. They take a `run` callable, such as Invoke's `c.run`, and return results such as the failed image names. `tasks.py` turns those into `Exit` errors.
- Put a package's unit tests in `devel/<package>/test/`, without an `__init__.py`. pytest imports test files with `--import-mode=importlib`, because test files in different packages can share names such as `test_testing.py`.
- In tests, import modules, such as `from devel.images import testing`, not functions whose names start with `test_`. pytest would collect an imported `test_images` as a test.
- Name an Invoke parameter that would hide a built-in with a trailing underscore. Invoke strips it from the flag, so `filter_` is still `--filter`.
- Feature scripts run on the container's system Python. See [Feature scripts](README.md#feature-scripts) for what they can import.

## Claude Code hooks

- `.claude/settings.json` runs `.claude/hooks/validate_image_manifests.sh` after each Edit or Write. When the edited file is a manifest, a template, the schema or `devel/images/manifest.py`, it runs the same checks as `invoke validate images` and exits 2 with the errors. Run it with `--all` to check without a hook event.
- Hook logic is Python in `devel/hooks/`, not `.claude/hooks/`, because Pyright doesn't check files in dot-directories. The `.claude/hooks/` wrapper runs it with the project's `.venv` and `python -I`.
- `devel/hooks` is on pytest's `pythonpath` and Pyright's `extraPaths`, so its tests import a hook as a top-level module.

## Shell conventions

- Image tests are POSIX `sh`, because `/bin/sh` in the Ubuntu images is dash. Don't use Bash features such as arrays or `[[`.
- `test.sh` sources `./test_utils.sh`, calls the `check` helpers and ends with `report_results`. Without `report_results`, the script exits with its last command's status, so a failed check before the last one is lost.
- `test_utils.sh` prints everything to stdout, so the output stays in order when podman streams it.
- Each image's test folder has its own copy of `test_utils.sh`, because only that folder is mounted in the container.
